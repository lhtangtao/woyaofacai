# 交易手续费与持久化

用户规则确认：2026-10-24。维护者：Codex。

## 费用规则

- 第一证券 FIRSTRADE：每笔实际券商成交费用为0。
- BBAE：按现有账务日business_date判断，2026-07-01之前为0；2026-07-01当天起每笔原始券商订单合计USD 1。先计算订单费用，再分给人员；没有订单ID时一条原始券商成交记录作为一笔，不把人员份额当成多笔订单，也不凭相同证券/时间擅自合并成交。
- 长桥 LONGBRIDGE：读取订单详情charge_detail.total_amount及currency；费用项目一并保留。未返回费用或币种不一致，不冒充零费用。仍在成交中的订单不持久确认为最终费用。
- 嘉信 SCHWAB：读取历史交易接口的明确费用项目，累计transferItems中有feeType的USD货币项cost的绝对值；仅有真实返回的零费用项目才能确认为0，不能用净金额与估算成交额的差额猜手续费。原始活动ID对应当前账本SCHWAB:activityId；API orderId作为附加证据保留。
- 内部人员划转 OWNER_TRANSFER：双方费用均为0，不摊入同日市场订单。

长桥字段依据：[官方订单详情](https://open.longbridge.com/zh-CN/docs/trade/order/order_detail)。嘉信字段按当前真实API响应核对；SDK只是HTTP封装，不能用券商通用费率代替实际费用。

## 分摊与历史匹配

- 一个真实订单对应多条券商成交时，先按成交股数分配订单总费用；每条券商成交再按人员股数分配。分摊覆盖所有人员，包括被筛选隐藏或停用人员，不随当前界面筛选变化。
- 使用整数1e-8金额。整数除法后按余数大小、稳定ID顺序分配尾差，最终合计严格等于订单费用。表格遇到分以下的分摊值显示至8位有效小数，避免三人各显示0.33却看不到尾差。
- 数量不守恒，或账户/证券/方向不一致时，相关人员费用保持未知，不按错误分母分配。订单费用与人员份额不混为同一账本重复累计。
- 有API订单ID时优先使用ID；旧长桥记录无ID时，核对日期、证券、方向、数量、价格和时刻，优先完整时刻一致；仅日期等属性时要求API及源流水中均唯一。价格、数量或重复候选存在冲突，不做模糊匹配。旧长桥SOURCE_RECORD可在有精确API证据时尝试历史美东时钟，须按夏令时转换并要求绝对时刻及其他属性逐项唯一一致；证据存clock_evidence，不改变原时刻或收益。
- 日期和SDK时间转换遵守TIMEZONES.md。这里只绑定费用证据，不改写原成交时钟或账务日期。

## 数据库存储与复用

- broker_trades.fees_e8：该条券商成交费用。
- order_fee_evidence：以渠道、账户、API订单/交易ID为键，保留实际金额、币种、成交数量、费用明细与来源，已确认的费用不重复调用API。
- broker_fee_records：券商成交的费用来源、状态和原记录指纹。
- person_trade_fees：人员分摊费用及参与计算的人员、账户、数量、时间、金额快照。
- 修改人员归属或数量后，刷新本地分摊；已确认订单费用仍复用。接口失败或缺少证据的订单才补查。已确认的0同样缓存，不因值为0重查。
- 展示层只读查询；费用快照与当前记录不一致时不展示旧费用。旧的无费用扩展表数据库依然能打开，市场订单费用显示待获取。
- 默认数据同步会重新应用本地规则和分摊；完整API同步结束后只为缺失费用补查API。切页、刷新表格不会触发费用网络请求。
- 补齐入口：`.venv/bin/python scripts/backfill_fees.py --fetch-api`。首次补齐前会在reports/fees保存数据库一致性备份，API成功的费用逐笔持久化，失败不覆盖已有证据。

## 金额与收益口径

本次仅补齐和展示手续费，不修改calculation_amount_e8、person_operations.amount_e8、持仓数量、原始交易时间、现有收益回放或Excel。嘉信的成交金额可能已是含费净额，不能再从其收益重复扣费。是否将其他渠道手续费统一纳入收益，需要独立核对净额/总额口径后实施，不能因补齐费用列顺便改变历史收益。

首次回填会保存各渠道覆盖率、未知原因及人员合计核对结果到本机reports/fees。数据库、备份、原始API响应与个人明细不提交Git。
