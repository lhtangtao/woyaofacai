# 年度走势图专项修复记录

修改者：Codex（代码修改）。本轮只读诊断与临时副本验证；不在生产库全量重算。

## 阶段一：已复现的根因

- 相同交易日，个人范围可读取真实五分钟明细；全部启用人员范围因部分历史人员分区仍为旧算法/INVALID而返回零组合点。不能把尚未包含全部人员的金额伪装成完整组合；需要修复后台发布顺序和推进速度。
- 后台按人员优先处理全年，历史补齐每轮仅一天；前面的人员已有一年数据，后面的人员尚未发布，组合长期被阻塞。
- 个人上半年实际有123个日期的五分钟明细；其中价格缺失、账本/时刻未确认导致部分点不可汇总，不能一概归因于行情不存在。代表日已核对为1/15、3/16、6/15、8/17、10/27。
- 年度采样只接受两小时网格前五分钟的点，已复现区间内有真实有效点但整点无点而被丢弃。
- 累计量一旦为未知就永久传播；必须重新以可信完整日报前缀或明确历史锚恢复，不能跳过未知期间从零开始。
- 读取时先装入全年逐股票明细再检查分区，重复逐人查询相同日期行情版本；Qt每次绘点和标记又线性查找categories.index。均与正常只读展示所需的工作量不符。

逐日A—F分类与月度计数保存在本机被Git忽略的exports/year-diagnosis-20261028目录，不上传真实财务数据。用户已确认“个人／全部渠道／全部股票”。全部人员分区不足是另一个已复现问题，不能替代个人范围根因。个人范围在诊断期间由可读变为失效，实际日志记录了历史手续费变化，随后后台逐日恢复。

## 后续验证要求

在临时源库/行情库/派生库副本上选择上述代表日重算、核对逐股票数量/基准/现金流/金额并保存，再重复查询验证。验证完成前不宣称全部年度数据已经恢复。

## 阶段二：针对性修复

- 保留有效性校验：真实历史手续费/交易变化必须失效；改为按日期完成全部历史人员、先最近日期，再持续批量推进缺失分区。异常分区记录原因并继续，已有价格和有效结果复用。
- 五分钟事实追加仅影响对应日期；每日收盘修正仍由独立依赖影响后续基准。重复历史价格无需写锁，避免日常采集与回溯相互阻塞。
- 查询先检验人员/日期/版本，再以Decimal聚合所需贡献；保留未知语义、授权人员覆盖与发布版本保护。聚合结果有限复用，未改变财务算法版本。
- 年度两小时/月度半小时区间选取真实五分钟点并保留实际时间；缺失段显式断线。日收益未知后，只允许用同一期初、完整已知买卖现金流及可信日末估值核对并恢复累计；未知现金流或账本不能恢复。
- Mac后台完成查询与曲线整理，主线程只显示；在途同筛选刷新不重复取消。绘图位置索引替代三处线性查找。Web使用同一聚合/采样/基准服务。
- 临时数据库副本的五个代表日各288点、共33984条证券明细，重算数值与旧值完全相同；重复增量写入不改值；查询聚合与逐股原始结果一致。6/15存在无法确认成交时刻的证券，保留未知。

未执行生产重算、pytest、E2E、完整构建或界面验收。生产库正在被用户程序更新，跨时刻覆盖数不可直接当作修复前后对比；副本验证才用于金额不变性结论。
