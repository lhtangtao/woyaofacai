# 交易明细与订单追溯 V1

修改者：Codex（代码修改）。本次仅改交易查询/展示链路，不迁移表结构、不修改真实交易、财务公式或派生算法版本。

## 已接入的页面与接口

- Mac：`TradeCenterPage` 使用独立局部控件、既有冻结表格及后台 Worker；不读取/覆盖其他页面的全局筛选。
- Web：`TradesView`、`TradeDrawer` 使用同一 Python 服务；窄屏详情覆盖显示，宽屏右侧抽屉可调整宽度。
- `GET /api/v1/trade-center`：完整匹配统计、分页明细、筛选选项、授权人员（含停用历史人员）。
- `GET /api/v1/trade-center/<record_id>`：按真实操作记录 ID 获取四标签详情、可靠关联记录及当前完整结果的前/后记录。`source_record_id` 只作来源追溯，不再混当交易 ID。
- `GET /api/v1/trade-center/export`：保持当前查询与排序，分批流式 CSV。旧 `/trades` 接口保留兼容。

两端默认2025-01-01至今天，人员为全部可访问人员；默认按解析后的成交时刻降序，每页200条。表内北京时间展示，原账务时钟、真实UTC和日期型估算说明保留在详情。纯日期沿用既定美东09:30估算，不冒充精确成交时刻。

## 数据口径

列表使用人员权益操作账本，不与券商真实成交账本相加。总数为匹配操作记录数，包含有效划转/结算；买入、卖出统计限定市场交易。SQL针对全部匹配记录统计、排序、分页，先筛选后分页。

金额来自原始e8字段，沿用原成交金额口径，费用独立展示、不重复加入金额。Python整数聚合与Decimal用于准确求和；不同币种分别统计。任一匹配记录费用不可信时，该币种费用合计显示未知，并保留缺失条数。当前价来自共享行情缓存，缺失时读取不晚于当前日期/时刻的数据库参考价；旧报价、收盘参考及缺报价时间明确区分。

成交前后持仓、净投入成本、每股成本变化使用既有回放、开账基准、拆股、划转规则及引擎成本差额；同一批记录批量查询，既有派生月度单元有效时复用，进程内按真实依赖内容复用批量结果。冷缓存只回放涉及的人员/账户/证券，在后台执行，不使用当前持仓反推历史。

默认15列：交易时间、券商渠道、归属人员、Ticker、分类、交易方向、当前价、成交价、成交数量、成交金额、手续费、成交后持仓、成交后成本价、成本变化、操作。成本变化为每股成本差额，建仓/不变/降低/提高/未知独立显示；非普通市场事件不套用普通买卖成本变化文案。

高级筛选支持数量/价格/金额/每股成本变化范围、来源类型/文件、关联状态、待核查及影响持仓。派生字段筛选/排序先批量取得对应有效投影，再在完整结果上筛选排序；不会仅排序当前页。无此类条件时只投影本页成本。

## 缺失与边界

- 现有微操报表是配对计算，不等于已核实的逐笔标记；本版明确提示暂不支持逐笔微操筛选。
- 现有净投入成本引擎未提供可信逐笔已实现盈亏，本版显示未提供，不用价差自行推算。
- 非USD记录原币金额、数量、费用仍可查询/分币种统计；历史成本引擎不在本次新增币种公式，相应历史成本状态未知。
- 旧记录时钟异常遵守现有 `TIMEZONES.md`，本版不扩展既定时区规则。
- 缺失/异常成本和行情显示“—”或具体状态，不补零；待核查记录保留原始证据。
- 详情关联只用同账户同证券订单、明确的成交关联或同一划转来源；不按相同代码/相近日期猜测关系。关联最多展示200条并提示截断。

## 权限与安全

沿用 `CAP_VIEW_ASSETS` 与现有 AuthContext 人员授权。列表、详情、统计、关联、前后导航及导出均保留授权范围；人员选择目录也只返回授权人员。受限账号不返回共享原始载荷全文；来源详情继续调用既有脱敏工具。页面只读，不增加下单、修改或删除。

导出全部匹配记录，每批500条，包含币种、订单、成交、来源ID与报价/成本状态；使用既有CSV公式注入防护。Mac切换数据源时取消旧任务并清除旧结果；顶部取消查询同样取消本页任务。Mac后台独占创建文件，不覆盖同名用户文件，失败只移除本次创建的半成品。Web流式读取，连接结束时关闭生成器。
