## 1. 用户已确定的产品决策（不得擅自更改）

1. **运行 Money Portfolio 的 Mac 与访问设备位于同一个物理局域网时，直接免输入账号密码**。无需维护 Wi-Fi 名称白名单、网络授权、设备授权、MAC 地址列表或一次性配对。Mac 连网线、手机连同一路由器下的 Wi-Fi，也属于典型局域网场景。
2. **通过公网、手机数据网络、异地 Wi-Fi、Tailscale 虚拟网络远程访问时，必须通过账号密码认证**，不能把 Tailscale 地址当作本地免密地址。
3. **免登录 ≠ 管理员登录**。局域网匿名访客使用专门的只读 `LAN_VIEWER` 权限身份。可以查看资产、持仓、报表、行情、K 线及技术指标；不得更改用户账户、密码、权限、推送配置、监控规则、数据库、交易流水、AI 会话等内容。需要这些操作时显式使用管理员或有权限的普通账号登录。
4. 任何同一局域网的设备都会自动具有上述只读访问能力，这是用户**明确接受**的产品行为。软件必须在设置页清楚提示局域网内其他设备也能查看开放的资产数据；不应声称“只有自己的手机才能看”。
5. 远程登录保留多人账户和人员级数据隔离。例如普通用户只能看自己有权查看的资产及交易；管理员可查看全量。**局域网只读全量展示是特设的产品策略，不等于给访客管理员角色**。
6. 应用仍是 **Mac 本机运行的服务**，不需要额外云数据库，也不要求后台云端守护进程；公网连接可以依赖已有 Tailscale / 用户自行配置的安全远程入口。
7. **所有财务原始数据库只读，绝对不改写原始持仓和交易数据。** 安全账户数据库和会话数据库可另建在 macOS 应用数据目录，不得提交 Git。
8. **一次性完成所有本 PRD 功能**。不接受只有 UI、只有模拟登录、或仅部分 API 加鉴权的交付。

### 1.1 对“同一个 Wi-Fi / 局域网”的操作性定义

- 不根据客户端宣称的 SSID、Wi-Fi 名称或 HTTP 请求头判断。Web 服务端无法可靠地从每个 HTTP 请求获知对方正在连接哪个 Wi-Fi。
- 以 **直接连接主机实际物理 LAN 接口的 TCP 对端地址**、该接口 IPv4/IPv6 地址和子网范围进行判定；必须排除 VPN、Tailscale、Clash/TUN、Docker、虚拟网卡和回环误判。`127.0.0.1` / `::1` 仅是 **Mac 本机**。
- 同一路由器的 Mac 网线 + 手机 Wi-Fi，只要两者实际互通且位于本地允许的子网，免登录；启用 AP 隔离、访客网隔离时可能无法连接，这不是软件认证失败。
- **不能仅因为远端 IP 属于 `192.168/16`、`10/8`、`172.16/12` 就放行**：公网代理、NAT、VPN 和网关可能产生这些地址。必须结合服务入口、接收接口、可信反向代理与真实对端进行判断。
- 如果存在公网端口转发、NAT 回流、网关 SNAT、反向代理等拓扑，导致服务器无法可靠区分外部来访和物理 LAN 来访，则**默认要求登录（安全优先）**，或改为物理 LAN 与远程入口分离；不得假装已安全识别。

## 2. 背景与现有代码审计结论

当前项目 Web 入口为 `src/portfolio/web/app.py`，页面为 `src/portfolio/web/templates/mobile.html`，运行入口包括 `启动手机服务.command` 和 `run_mobile_server()`。基于编制时读取的源码，存在以下必须修复的缺陷：

| 编号 | 现状 | 问题 / 风险 | 处理要求 |
|---|---|---|---|
| SEC-01 | `get_current_user()` 在无 session 时回退 `{username: admin, role: admin}` | 无凭据访问默认管理员 | 删除默认管理员回退；改为匿名无权限或经判定的 `LAN_VIEWER` |
| SEC-02 | 接受 `X-User` 请求头、`auth_user` 查询参数指定用户 | 未经密码验证的用户冒用，破坏人员资产隔离 | 完全移除这一认证路径；如有内部脚本依赖，迁移至独立、受认证的接口 |
| SEC-03 | `DEFAULT_USERS` 包含明文示例密码，网页还有快速填充账户逻辑 | 静态密码泄露 / 默认账户风险 | 不再提供任何可登录的默认密码，移除界面明文提示和快速填充 |
| SEC-04 | `app.secret_key` 存在可预测固定默认值 | 会话完整性风险 | 随机生成密钥，在本机安全保存，不允许弱默认回退 |
| SEC-05 | `logout` 后又调用默认管理员身份 | 退出登录可变为管理员视角 | 退出后恢复为 LAN 匿名只读或远程未登录，不再恢复管理员 |
| SEC-06 | 报表、交易、AI、监控等路由大多直接依赖 `get_current_user_scope()` | 仅“计算范围”不足以保护 API；缺少统一资源和操作鉴权 | 全路由权限清单 + 全局服务端认证授权保护 |
| SEC-07 | `/api/rules/<rule_id>/toggle`、`/api/ai/clear`、`/api/bark/config` 等可修改状态 | 未授权操作可能改写本机配置/共享数据 | 强制授权 + CSRF 保护 + 操作审计 |
| SEC-08 | 页面显示“登录/切换用户”“重置管理员” | 容易误导用户把切换身份当成登录 | 改为清晰的“局域网访客 / 已登录用户 / 远程未登录”交互 |
| SEC-09 | Web 服务默认监听 `0.0.0.0:8888`，以 `app.run()` 启动 | 不适合作为直接暴露公网的生产部署入口 | 提供稳定 WSGI 启动及安全远程接入说明；禁止直接对公网暴露 Flask 开发服务器 |

**重要**：上面是静态代码审计结果，不代表已进行了端到端渗透测试。Codex 必须检查实际运行路径、打包行为和相关调用方，防止漏改。

## 3. 目标与非目标

### 3.1 目标

- 在同一个真实局域网使用移动端时开箱即用，打开网址即可看到资产和股票行情。
- 异地使用 Tailscale 或经 HTTPS 公开入口访问时先登录，再按账户权限查看数据。
- 无论使用浏览器界面、直接请求 REST API、刷新页面还是深链访问，权限结果一致。
- 不让匿名局域网访客意外获得管理员身份、写权限或后台系统操作权限。
- 修复默认账户、固定密钥、伪造用户、权限绕过、CSRF、弱会话、暴力登录等基础安全问题。

### 3.2 非目标

- 不实现 Wi-Fi SSID 白名单、设备绑定、首次设备批准、短信验证、云端 OAuth 等额外流程。
- 不强制局域网访客创建账号。
- 不改变 PySide6 桌面端本地使用方式，不重构金融计算和账务引擎。
- 不将 Money Portfolio 变成可让不受信任公众匿名注册的多租户网站。

## 4. 访问模式与授权矩阵

### 4.1 访问场景

| 场景 | 身份判定 | 用户体验 |
|---|---|---|
| Mac 本机 `127.0.0.1` / `::1` | LOCAL / 未登录只读访客 | 免账号密码看资产和行情；管理操作需登录 |
| Mac 有线，iPhone 同一路由器 Wi-Fi | LAN_VIEWER | 免账号密码看资产和行情 |
| Mac Wi-Fi，iPad 同 LAN | LAN_VIEWER | 免账号密码看资产和行情 |
| 另一台同 LAN 的 Windows | LAN_VIEWER | 免账号密码看资产和行情 |
| 同一 Wi-Fi 但 AP 隔离导致不可达 | 无法连接 | 展示连接故障说明；不降低服务端安全要求 |
| 4G/5G，公网地址 | UNAUTHENTICATED | 显示登录页；未登录 API 返回 401 |
| 酒店/异地 Wi-Fi + 公网域名 | UNAUTHENTICATED | 必须登录 |
| 远程 Tailscale (`100.64.0.0/10` 等) | UNAUTHENTICATED | 必须登录，即便 Tailscale 显示私网地址 |
| 普通公网反向代理 | UNAUTHENTICATED | 必须登录；不能因为后端看见 `127.0.0.1` 就免登录 |
| 已用账号登录的任意访问网络 | AUTHENTICATED | 按账户角色和人员授权访问；满足会话安全约束 |

### 4.2 权限角色

- `LAN_VIEWER`：局域网匿名只读角色，**不是 admin**；可查看完整资产数据视图（用户确认接受此公开范围）。不保证资产归属到具体局域网访客。
- `ADMIN`：经密码验证的管理员，拥有全量查询和经过授权的配置修改能力；关键安全操作还需近期重认证。
- `USER`：经密码验证的普通用户，仅能访问授权人员 `person_id` 的资产、交易、AI 私人会话和相关数据；不能借由请求参数切换到别人。
- `UNAUTHENTICATED`：不在可信 LAN 且无有效登录；仅能获取登录所需的公开页面/静态资源和最小状态信息。

### 4.3 功能权限（默认策略）

| 功能 / 资源 | LAN_VIEWER | ADMIN | USER | 未认证远程 |
|---|---|---|---|---|
| 首页骨架、登录页、必要静态资源 | 允许 | 允许 | 允许 | 允许 |
| 资产总览、当前持仓、报表、图表、只读交易明细 | 查看全量 | 查看全量 | 查看本人授权范围 | 拒绝 |
| 行情监控观察列表、K 线和技术指标 | 查看 | 查看 | 查看允许范围或公共行情（按产品权限统一定义） | 拒绝 |
| 监控规则 / 报警历史 | 只读展示，不得泄漏推送密钥等配置 | 允许 | 只读本人可见范围，写入需显式授予 | 拒绝 |
| 创建/启停/删除监控规则 | 拒绝，需要显式登录 | 允许 | 默认拒绝；按明确授予的权限决定 | 拒绝 |
| AI 投资问答请求 / 删除会话 / 专属会话历史 | 默认拒绝，需要显式登录（保护本地私密会话和计算资源） | 允许 | 仅本人有权范围 | 拒绝 |
| Bark 推送 URL、测试推送、配置、账户管理 | 拒绝 | 允许（敏感操作需重认证） | 拒绝 | 拒绝 |
| 导出敏感报告、上传/修改本机文件、管理数据源 | 拒绝 | 由管理员授权清单控制 | 默认拒绝 | 拒绝 |
| 查看身份 `/api/auth/me` | 返回 `LAN_VIEWER` / 不暴露敏感信息 | 返回本人 | 返回本人 | 返回未登录状态 |
| 登录和退出 | 允许 | 允许 | 允许 | 允许 |

### 4.4 数据访问范围与多人资产隔离

- `ADMIN`：全量人员/渠道/股票。
- `USER`：只允许关联的 `person_id`，即使 URL、JSON body、HTTP header 声称其它 `person_id` 或 `person`，也必须由服务端强制过滤。
- `LAN_VIEWER`：按用户明确的局域网免密方案，可查看全量**只读**投资视图；页面须提示“同局域网设备可查看”。不应把此角色映射成 `ADMIN`，不能使用 `person_id=None` 即隐式获得所有管理能力。
- 所有数据查询与导出/API 计算按 `AuthContext` 约束；禁止仅靠前端隐藏控件限制权限。特别检查共用 AI 会话文件、聊天记录、监控事件、Bark 配置和其他敏感字段。

## 5. 网络识别与安全接入设计

### 5.1 必须采用服务端判定

分类输出至少为：

```text
LOCAL_LOOPBACK / DIRECT_PHYSICAL_LAN / REMOTE_TAILSCALE / REMOTE_PUBLIC / UNKNOWN
```

优先读取服务端实际 TCP peer、连接实际进入的监听端点/接口、macOS 物理网卡及其活动子网，建立允许自动免密的**直连物理 LAN**范围。

允许 IPv4/IPv6；`100.64.0.0/10`、VPN/TUN/TAP/utun、其他虚拟接口、Tailscale、代理转发、未知拓扑一律不能直接得到 LAN 免密资格。对于 IPv6，不能单凭 ULA / link-local 前缀判断为 LAN，必须与本机实际接口/区域相匹配。

### 5.2 建议的入口隔离（强烈要求）

**LAN 接入**与**远程接入**尽量分离到独立监听入口 / 安全代理配置，避免公网流量被本地网关 SNAT 成局域网地址后绕过认证：

```text
Mac 本机访问 ─────────────┐
同物理 LAN 直连 ──────────┤→ LAN 入口 → 后端统一权限层 → 只读 LAN_VIEWER（或已登录者）
                         │
Tailscale / 公网 HTTPS ──┘→ REMOTE 入口 → 后端统一权限层 → 未登录 401 / 登录后按角色授权
```

- 分离入口的“LAN / REMOTE”信任标识必须来自部署层已验证的监听端点/受控服务端上下文，**不得由任何客户端传入的 `X-LAN-User`、`X-Trusted-Network` 等 Header 决定**。
- 如果沿用单入口，必须提供防公网源地址转换/回源混淆的实测证明；不能证明时优先改成入口隔离，否则禁止直接开放 WAN 入口。
- 不默认信任 `X-Forwarded-For`、`X-Real-IP`、`Forwarded` 或 Host 头；如明确部署了受控反代，必须限定可信代理来源、正确代理跳数、消除外部伪造字段，并确保代理不会把公网流量降格为 LAN。
- 不应把浏览器在 Wi-Fi 上的事实当作后端权限凭证；也不可用 JS 判断网络环境决定 API 权限。

### 5.3 失败策略

- 网络接口、子网、路由、可信代理或监听入口信息无法识别：归类 `UNKNOWN` → **要求账号密码**。
- 网络状态变化（Mac 换网、iPhone 从 Wi-Fi 切 5G、Tailscale 启停）在下一请求重新评估；匿名 LAN 身份不允许跨网络复用为公网身份。
- 不因 IP 与 MAC、SSID 相似而自动提权；不缓存永久的“免密资格”。
- 如果 Mac 上启用了公网端口映射且无法保证入口隔离，设置页面显示红色安全警告，远程入口保持强制认证。

## 6. 认证与会话

### 6.1 账号配置

- 移除可登录的硬编码 `DEFAULT_USERS` 密码。已有配置中的明文密码必须一次性安全迁移或要求重新设置；**公开过的示例密码必须作废**。
- 初始化管理员仅允许 **Mac 本机交互**（桌面设置页或本地 CLI），不得在尚未初始化时放开远程无认证管理员创建。
- 管理员可新建/停用普通用户、设置关联 `person_id`、重置密码；本机认证数据独立存储，例如 `~/Library/Application Support/MoneyPortfolio/` 下的专属 SQLite，权限限制为当前 macOS 用户可读写。
- 密码使用 Argon2id（优先）或 scrypt/PBKDF2 等成熟密码哈希算法，并为每个账户生成随机盐；不得保存或记录明文密码，不得明文提交 Git。
- 登录失败限流（账号 + 客户端 IP）、渐进延迟、通用错误提示、审计日志，不暴露“用户名是否存在”。

### 6.2 Session

- 随机高强度会话密钥；不得保留可预测的 `FLASK_SECRET_KEY` 默认值。密钥持久化安全保存并设置本机文件权限，密钥变化可使旧会话失效。
- 建议采用**服务器端会话**：Cookie 仅保存随机会话标识；服务端保存用户 ID、角色、人员授权、创建时间、最后活动时间、撤销状态，并能真正执行“退出当前设备 / 退出全部设备”。
- Cookie：`HttpOnly`、`SameSite=Lax/Strict`、合理的 Path 与 Domain；**远程登录必须走 HTTPS 并设置 Secure**。本机/内网 HTTP 与远程 HTTPS 的 Cookie、端口和域名策略需明确设计，不能为了 HTTP 兼容导致远程 Cookie 不安全。
- 空闲超时建议 12 小时；最长会话建议 7 天（管理员安全操作仍需重新验证密码）；值可本地配置。管理员修改密码后撤销已有会话。
- 登录成功刷新会话 ID，防会话固定；失效、注销或账户被禁用后所有后端接口立即拒绝旧令牌。
- CSRF：所有基于 Cookie 的状态变更（POST/PUT/PATCH/DELETE，包括登录、登出）使用 CSRF Token，并校验 Origin/Referer；仅 `SameSite` 不足以代替 CSRF 防护。

### 6.3 退出登录规则

- 在公网/Tailscale：注销后显示未登录页，所有受保护 API 返回 401。
- 在直连 LAN：注销后回到 **LAN_VIEWER 只读视图**，而不是管理员。
- 在局域网内曾登录为 `USER`，退出后重新展示 LAN_VIEWER 的只读全量视图，前端明确标记访客状态；如用户不希望 LAN 内其他人看全量，应关闭 LAN 免登录策略，而不是伪装个人数据隔离。

## 7. 权限架构与 API 落地

### 7.1 统一的 AuthContext

为每一个请求生成独立的、**仅由服务端计算**的 `AuthContext`（概念示意）：

```python
@dataclass(frozen=True)
class AuthContext:
    access_mode: str      # LOCAL_LOOPBACK / DIRECT_PHYSICAL_LAN / REMOTE...
    principal_type: str   # LAN_VIEWER / ADMIN / USER / UNAUTHENTICATED
    user_id: str | None
    allowed_person_ids: tuple[int, ...] | None
    capabilities: frozenset[str]
    is_authenticated: bool
```

处理顺序：网络来源检查 → 读取/校验登录会话 → 决定 principal → 检查本 API 是否授予该 capability → 数据查询按人员范围强制过滤 → 返回结果。

**匿名身份必须显式具有有限权限，不允许使用“person_id=None 就是 admin”的隐式判断。**

### 7.2 全局保护与 API 清单

- 用 `before_request` / 装饰器 / 权限路由注册表统一控制全部 `/api/*`，未标记端点默认拒绝。
- 对 `/api/overview`、`/api/report/<report_name>`、`/api/reports/list`、`/api/trades`、`/api/charts` 和所有新旧报表/图表接口：仅授予可读取的身份，并落实个人数据权限。
- `/api/monitoring/symbols`、`/api/monitoring/kline`、`/api/monitoring`：允许 LAN 只读；按登录权限决定是否暴露规则细节及人员信息。
- `/api/rules/<rule_id>/toggle`：强制有 `monitor.rules.write` 权限，校验 CSRF；监控规则由谁拥有、谁可以修改要有稳定的服务端所有权规则。
- `/api/ai/history`、`/api/ai/clear`、`/api/ai/chat`、`/api/ai/stock/...`：必须逐一核对隐私范围和成本/副作用；LAN_VIEWER 默认不能访问私人聊天或调用 AI，若有公开股票研究仅能访问不包含私人数据的明确只读结果。
- `/api/bark/config`、`/api/bark/test`：仅管理员，并不得返回完整 Bark 密钥 URL；读接口同样要做脱敏。
- `/api/network/info`：不向未登录公网访客泄露本机所有 IP、Tailscale 详细地址等；确有展示需要则使用不同角色的脱敏响应。
- `/api/auth/me`：返回角色、`authenticated`、`login_required`、`access_mode`、允许功能摘要，不包含密码哈希/会话密钥。
- 检查模板、图片、静态文件、导出目录、源码路由、调试端点；静态公开文件不得包含真正的 Token、私人数据、默认密码或能触发业务操作的能力。
- 错误码标准化：未认证 401、已认证/访客但无权限 403、CSRF 失败 403、过量登录请求 429。失败时不得返回资产数据。

### 7.3 禁止的绕过路径

- 删除 `X-User` 和 `auth_user` 作为身份依据。
- 彻底移除“退出后自动管理员”和“无 Session 即 admin”逻辑。
- 用户角色、人员 ID、API Key、管理员状态不信任浏览器传入；普通账号不能通过改变 URL/body 查询他人的资产。
- LAN_VIEWER 不能通过把 `role=admin`、`person_id=None`、修改 Cookie 值等方式提升权限。
- 不允许未授权调用 AI Chat 清理、行情规则 toggle、Bark 推送配置或写入相关本地文件。

## 8. 前端 UX / 原型文字规格

### 8.1 局域网免登录页面

打开 `http://<Mac局域网IP>:8888` 后直接展示首页，不出现登录弹窗；右上角身份标签：

> `🛜 局域网访客 · 只读`　[使用账号登录]

禁止出现“管理员”“已登录管理员”的误导字样。匿名访问时隐藏或置灰编辑按钮，用户点击写操作应显示“请先使用有权限的账号登录”，但**后端依然必须返回 403**。

### 8.2 公网远程页面

访问远程入口显示简洁登录页：

```text
Money Portfolio
安全远程访问

账号      [________________]
密码      [________________]
          [ 登录 ]

当前为远程连接，登录后可查看授权的投资信息
```

未登录状态不能先后台发起 `/api/overview`、`/api/trades` 等敏感请求或在页面源代码嵌入全部持仓数据。登录成功再请求资产 API。

### 8.3 显式登录与切换账户

- 即使在局域网，用户仍可点“使用账号登录”，切换成自己或管理员并获得相应权限。
- 登录身份切换要验证密码。不能仅点击姓名或修改 `X-User` 就切换。
- 删除页面预填的 `admin/admin`、`拉科/lake` 等弱密码示例以及 `quickFillUser` 快捷填充。
- 退出管理员：在 LAN 回到只读访客；在远程回到登录页。

### 8.4 设置页（Mac 管理员本机或管理员账户可见）

展示“访问安全”状态卡，包括：

- `局域网免登录：开启`（按本 PRD 固定启用，无 Wi-Fi/设备授权管理页）

- `远程入口 / Tailscale 当前可用状态`
- `安全异常：发现代理、未知网络或无法判定则要求登录`
- `登录账户管理、密码修改、会话撤销、安全日志`

展示警示：“只要处于同一可访问的局域网，其他设备也能免密码查看你的资产。不要在不可信的共享局域网中开启服务。”

## 9. 部署和连接要求

1. 保留桌面端及 `启动手机服务.command` 的原用法，正常情况下端口仍可为 `8888`。
2. 不向公网直接暴露 Flask 开发服务器；改用适当的生产 WSGI 服务组件或安全反向代理，并保留 Mac 双击启动的便捷性。
3. 远程入口需有加密传输：Tailscale 自身有加密隧道，但 Web Session Cookie / 浏览器 Secure 属性仍需合理设计；优先 Tailscale Serve / HTTPS 等受支持方式。公网域名必须 HTTPS，禁止以裸 HTTP 输入公网账号密码。
4. 不自动开启路由器 UPnP 端口转发，不自动修改系统防火墙。
5. 本机及 LAN 入口与远程入口的路由、监听地址和代理信任边界要写在 README；如采用同进程多入口，必须能自动化测试验证其安全标识不被用户伪造。
6. 仅将网络状态、登录失败、权限拒绝等必要元数据记入日志，不记录密码、Session Cookie、Token、Bark URL 或个人交易明细。日志做大小轮转和本地权限限制。

## 10. 数据结构建议

不得改变现有财务库；新增独立安全存储。例如：

```text
security.sqlite3
  users
    id, username, password_hash, role, person_id,
    enabled, password_changed_at, created_at, updated_at
  auth_sessions
    session_id_hash, user_id, issued_at,
    last_seen_at, expires_at, revoked_at
  auth_audit_events
    id, occurred_at, event_type, user_id,
    source_class, ip_masked, result, metadata_json
```

具体名称可由 Codex 按现有架构决定，但需满足迁移、索引、事务、安全权限、账户禁用后立即生效及同库多用户隔离。

`LAN_VIEWER` **不写入 `users` 表，不生成管理员 Session**；每次请求根据 LAN 入口身份动态判定匿名只读权限。

旧配置 `api_config.json` 的非认证 API 凭据、长桥/嘉信及 Bark 业务配置应保持兼容，不得将这些秘密迁入可下载的静态资源或 Git；旧用户明文密码在迁移后安全擦除或禁用并重置。若无法可信迁移，则应要求 Mac 本机重置管理员密码，而不能继续启用弱默认账号。

## 11. 错误处理、运行状态和审计

| 情况 | 后端 | 前端 |
|---|---|---|
| LAN 匿名访问资产 | 200，只返回允许查看的数据 | 直接显示资产，身份显示“局域网访客·只读” |
| LAN 匿名点击启停规则 | 403 | 提示需登录，不改变规则 |
| 远程未登录访问资产 API | 401，无资产数据 | 显示登录页 |
| 公网登录密码错误 | 401 | 统一错误，不暴露账号存在性 |
| 登录尝试过多 | 429 | 显示稍后重试 |
| 已登录普通用户请求他人数据 | 403 或按授权仅返回本人结果 | 无权访问提示 |
| 会话到期或管理员禁用账户 | 401 | 自动清理受保护页面数据并进入登录状态 |
| LAN / REMOTE 分类失败 | 401（除公开路由） | 要求登录，并显示无法识别网络 |
| CSRF 校验失败 | 403 | 请求未执行，可刷新重试 |
| 外部代理源地址可疑 | 不授予免密资格 | 展示远程登录 |

监测与排查日志应覆盖：登录成功/失败、登出、拒绝访问、来源类别变化、重大账户更改和会话撤销；不能因为保存调试日志泄露个人账户密码。
