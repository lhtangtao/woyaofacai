# 如何将此开发需求交给 Codex

这是一个可直接用于 Codex 的 Mac 投资管理软件开发资料包。

## 包内文件

- `docs/PRODUCT_REQUIREMENTS.md`：**主开发需求**，详细定义界面、13 Sheet、27 图表、18 个首页指标、SQLite 字段、公式、测试、里程碑。
- `Mac股票投资管理系统_Codex完整开发需求.md`：主需求的中文命名副本，方便直接阅读。
- `AGENTS.md`：Codex 持续遵守的项目级规则。
- `Codex_开工提示词.txt`：第一句话直接复制给 Codex。
- `references/sqlite_schema.sql`：你提供的 SQLite DDL 原件（从文本改名为 `.sql`）。
- `references/个人投资总览.xlsx`：旧投资报表原件，包括 13 个 Sheet、27 张图表。

## 建议使用方法（Mac）

1. 将整个压缩包解压到准备开发的项目目录，比如 `~/Documents/money-portfolio-desktop/`；让 Codex 能读到这些文件。
2. 在 Codex 中打开这个项目目录，复制 `Codex_开工提示词.txt` 中的内容，要求它从 M0 / M1 开始，并阶段性运行测试。
3. **如已有 Python 投资统计代码，请把它放到项目目录或让 Codex 能访问**，因为原来的微操配对、拆并股和开账口径可能只存在于代码里；Codex 应先检查旧代码再复用。
4. **如已拥有真实 SQLite `.db` 文件，后续可由你单独指定路径供 Codex 做只读核验**。此包内目前不含真实数据库，只有表结构和 Excel，不要把原数据库拷贝到 Git 仓库。
5. 首次 Codex 输出应是：扫描结果、当前项目架构、M0 数据字段映射、M1 可运行界面/查询骨架、已执行的测试清单。
6. 如果某个结果与 Excel 不一致，让 Codex 输出对应计算路径及“Excel vs SQLite”差异明细，而不是修改值凑结果。

## 重要的口径区别

旧 Excel 首页的“当前总资产”只计算股票市值；股票净投入不是外部入金；部分“浮动盈亏”是净投入保本口径而不是标准会计未实现盈亏。新软件应该同时保留兼容版统计和后续标准口径，不能混为一谈。

## 权益和隐私

你的 Excel 可能包含真实投资交易信息，不建议上传到公开代码仓库。建议把 `references/个人投资总览.xlsx` 加入本地 `.gitignore`，或在上传仓库前另做脱敏替代样本。真实 SQLite 数据库也应排除在版本控制外。
